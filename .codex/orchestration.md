# Оркестрация и агенты

## Рабочий поток

Для нетривиальной задачи: `READ → UNDERSTAND → PLAN → CODE → VERIFY`, обычно
`User → Astra → Terra → Astra → Sol → specialist review → verify → Astra`.
Простую правку не переоркестрируйте. Astra хранит состояние; Terra сначала ищет
существующие паттерны и тесты; Sol делает минимальное совместимое изменение.
Архитектурный вопрос возвращается Astra, продуктовое решение вне репозитория —
пользователю.

Если пользователь уже явно разрешил операцию в текущей сессии, повторное
согласование не требуется; действуйте в пределах данного разрешения.

## Обязательный контракт каждого агента

Первым блоком любого prompt агенту вставьте без ослабления содержимое
`docs/AGENT_PREAMBLE.md` с маркером `[ОБЯЗАТЕЛЬНЫЕ ИНСТРУМЕНТЫ]`. Это относится
к Agent, Explore, Plan, general-purpose, ECC-reviewers и субагентам. Хук
`scripts/hooks/require-agent-preamble.mjs` в `.claude/settings.json` блокирует
prompt без маркера; не отключайте и не обходите его.

Каждый агент обязан:

1. выполнить Graphify до чтения исходников, если граф доступен;
2. загрузить обязательные для задачи skills;
3. использовать Serena для символов;
4. использовать Context7 для сторонней библиотеки/API по версии репозитория;
5. применить Semgrep для security и браузер для UI-поведения;
6. закончить строкой
   `Использовано: skills=[…]; mcp=[…]; graphify=да/нет; не использовано: <причина>`.

Нет footer или необъяснимо пропущен обязательный инструмент — результат не
принимается, агент запускается заново. Главный агент проверяет вывод по исходникам,
diff или собственному запуску тестов; заверение субагента не доказательство.

## Делегирование

Prompt после preamble содержит цель, scope, владение файлами, известный контекст,
архитектурное решение, запреты, acceptance criteria, проверки и формат ответа.
До запуска убедитесь, что нужные skills и MCP доступны агенту.

Параллельная работа допустима для независимых подзадач. Сначала согласуйте API,
типы и схемы, назначьте непересекающиеся файлы и сохраните чужие изменения; после
слияния проверьте интеграцию. Учитывайте лимит конкурентности и переиспользуйте
агента с актуальным контекстом.

Если делегирование недоступно, корневой агент выполняет узкую работу и сообщает
ограничение; обязательные инструменты не отменяются. Нельзя придумывать запуск
агента, модель, MCP-вызов или проверку.

## Проектный поток

Новый источник проходит через решение Astra, исследование Terra и
`SourceAdapter` с тестом Sol; Python MCP может дать транспорт/парсер. UI начинается
с MSD-слоя и API-контракта, заканчивается live browser verification. Search/analysis
не смешивают сбор, детерминированный отбор и LLM-объяснение. Платный провайдер,
credential или операционное изменение требует решения пользователя. Прод меняется
через commit и `scripts/deploy.sh`; ad-hoc правки запрещены, `chrome-headed`
обычным деплоем не пересоздаётся.
