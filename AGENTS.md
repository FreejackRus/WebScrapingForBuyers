# Правила работы с WebScrapingForBuyers

Политика обязательна для всех задач и агентов. Подробности в пяти файлах ниже
дополняют корень и не являются необязательными.

## Перед работой

1. Прочитайте `README.md`, `docs/AI_SERVER.md` и актуальные записи
   `docs/PROJECT_CONTEXT.md`; проверьте dirty-файлы и не затирайте чужие правки.
2. Выполните `bash scripts/check-env.sh`. Это не доказательство, что каждый MCP
   авторизован и отвечает: нужный skill/MCP/plugin проверьте реальным вызовом до
   первой правки кода.
3. Для нетривиальной задачи при наличии графа сначала используйте Graphify, затем
   подходящие skills. Матрица и правила недоступности — в [tools](.codex/tools.md).
4. После заметной итерации добавьте датированную запись в
   `docs/PROJECT_CONTEXT.md`: решение, контур, проверки и ограничения без секретов.

Если обязательный инструмент не работает, сначала восстановите его. Если это
невозможно, остановите зависящую работу и точно сообщите блокер. Нельзя молча
подменять Graphify, Serena, Context7, skill, Semgrep или браузер догадкой.

## Роли

- **GPT-6 Astra (`gpt-6-astra`)** думает: оркестрирует, проектирует, принимает
  решения, согласует контракты и проверяет доказательства.
- **GPT-5.6 Terra (`gpt-5.6-terra`)** читает: исследует репозиторий, зависимости,
  документацию, логи и историю; обычно работает read-only.
- **GPT-5.6 Sol (`gpt-5.6-sol`)** пишет: реализует согласованные изменения,
  красные тесты и исправления, затем запускает проверки.

Skills специализируют процесс, MCP подключает системы, инструменты проверяют факты.
ECC-специалист дополняет модельную роль. Не заявляйте переключение модели или вызов,
которого не было. Подробнее: [models](.codex/models.md) и
[orchestration](.codex/orchestration.md).

## Архитектурные границы

- `packages/contracts` — общий API/UI-контракт без инфраструктуры;
  `packages/service-kit` — Fastify bootstrap без доменной логики.
- `apps/gateway` — единственная внешняя точка `/api/v1`, cookie-сессия и RBAC;
  `apps/identity` — вход, профиль и пароль.
- `apps/search` — каталог, сбор, SSE и Excel. Новый источник реализует
  `SourceAdapter`; существующий Python MCP может дать низкоуровневый парсер,
  но подключается через адаптер search. Парсинг источников запрещён в gateway,
  identity, analysis и web.
- `apps/analysis` детерминированно отбирает данные; LLM только объясняет.
- `apps/web` следует MSD из `docs/MSD.md`: `app`, `pages`, `widgets`,
  `features`, `entities` без UI, `composition`, `shared`; страницы собирают
  виджеты, расчёт закупки во фронтенде не живёт.

Демо всегда имеет `demo: true`; live, cache, fixture и stub различайте явно.
Платный источник — только по новому явному решению пользователя. Секреты и
`.env.server` не выводите и не коммитьте. Менеджер не видит инфраструктурные
детали и сырые ошибки. Прод меняется из committed ref через `scripts/deploy.sh`;
обычный деплой сохраняет `chrome-headed`.

## Завершение

Команды и Definition of Done — в [review](.codex/review.md), диагностика — в
[debugging](.codex/debugging.md). После кода выполните `graphify update .`;
docs-only правки граф не обновляют. В финале перечислите фактически использованные
skills и MCP, объясните пропуски. Не приписывайте ИИ авторство в коммитах, PR или
файлах; это не запрещает технические названия моделей в документации.
