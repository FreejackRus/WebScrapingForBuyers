# Сервер локальной LLM

Снимок ниже получен 23 сентября 2026 года по SSH командами только для чтения.
На сервере ничего не устанавливалось и конфигурация не изменялась.

## Характеристики

- ОС: Ubuntu 24.04.3 LTS, Linux 6.8.0-117-generic, x86_64.
- CPU: AMD EPYC 7302, 16 ядер / 32 потока, до 3,0 ГГц.
- RAM: 251 GiB; во время проверки доступно 245 GiB. Swap: 4 GiB.
- Диск: NVMe Samsung 2 TB; корневой ext4-раздел 1,9 TB.
- На первой диагностике было свободно 39 GiB (98% занято). Перед развёртыванием
  место было освобождено: повторная проверка показала 249 GiB свободного места
  (87% занято).
- GPU: 2 × NVIDIA GeForce RTX 4090 по 24 564 MiB VRAM (в сумме около
  48 GiB), compute capability 8.9. Во время проверки GPU были практически
  свободны.
- Драйвер NVIDIA: 580.82.07; `nvidia-smi` сообщает CUDA 13.0.
- CUDA Toolkit (`nvcc`) на хосте не установлен. Для контейнерного запуска он
  не требуется: CUDA runtime входит в образ, а используется драйвер хоста.
- Docker: 29.3.1.
- NVIDIA Container Toolkit: 1.19.0; runtime `nvidia` зарегистрирован в Docker.
  Default runtime остаётся `runc`, поэтому при запуске нужно явно указывать
  `--gpus all`.

## Рекомендация для MVP

Основной вариант: официальный
[`Qwen/Qwen3-30B-A3B-Instruct-2507-FP8`](https://huggingface.co/Qwen/Qwen3-30B-A3B-Instruct-2507-FP8)
под [`vLLM`](https://docs.vllm.ai/) с OpenAI-совместимым API.

Почему:

- модель многоязычная и пригодна для русского диалога, извлечения требований,
  сопоставления и ранжирования закупочных предложений;
- это instruction-модель с улучшенным tool calling; Hermes-вызовы инструментов
  vLLM возвращает в структурированном поле `tool_calls`;
- MoE имеет 30,5 млрд параметров, но активирует около 3,3 млрд на токен;
- официальный FP8 checkpoint лучше воспроизводим, чем сторонняя INT4-сборка, и
  размещается на двух GPU с tensor parallelism;
- vLLM даёт уже ожидаемый проектом OpenAI-совместимый интерфейс.

Для первого запуска контекст намеренно ограничен 32 768 токенами. Заявленные
моделью 262 144 токена не означают, что такой контекст практичен на 48 GiB VRAM:
KV cache и параллельные запросы быстро исчерпают память. Для анализа длинных
прайс-листов следует сначала отбирать/агрегировать строки, а не отправлять весь
каталог одним prompt.

### Место на диске

Первоначальный блокер снят: доступно около 249 GiB. Следует сохранить минимум
80–100 GiB свободного пространства для образов, кешей моделей и обновлений.

Проверка места:

```bash
df -h /
docker system df
```

### Запуск

Команды ниже являются инструкцией и во время диагностики не выполнялись.
API по умолчанию публикуется только на loopback. Перед запуском задайте
случайный ключ в текущей shell-сессии или через secret manager:

```bash
export VLLM_API_KEY='<set-in-shell-or-secret-manager>'
test -n "$VLLM_API_KEY"
```

После обеспечения свободного места:

```bash
docker pull vllm/vllm-openai:v0.10.2

docker run --rm \
  --name procurement-llm \
  --gpus all \
  --ipc=host \
  -p 127.0.0.1:8000:8000 \
  -e VLLM_API_KEY \
  -v /srv/huggingface:/root/.cache/huggingface \
  vllm/vllm-openai:v0.10.2 \
  --model Qwen/Qwen3-30B-A3B-Instruct-2507-FP8 \
  --served-model-name procurement-llm \
  --tensor-parallel-size 2 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.90 \
  --enable-auto-tool-choice \
  --tool-call-parser hermes \
  --api-key "$VLLM_API_KEY"
```

`/srv/huggingface` должен находиться на файловой системе с достаточным свободным
местом. Если такого mount point нет, его нужно заменить на фактический путь.

Проверка из той же машины:

```bash
curl --fail --silent \
  -H "Authorization: Bearer $VLLM_API_KEY" \
  http://127.0.0.1:8000/v1/models
```

Для доступа приложения с другой машины лучше оставить vLLM на loopback и
опубликовать его через внутренний reverse proxy с TLS и аутентификацией либо
через SSH/VPN-туннель. Не следует открывать порт 8000 в Интернет напрямую.

## Ограничения и проверка качества

- FP8 экономит память и обычно сохраняет качество лучше INT4, но результат
  необходимо проверить на реальных русскоязычных примерах закупок.
- Две RTX 4090 не имеют NVLink; обмен tensor parallelism идёт через PCIe.
  Следует измерить latency и throughput на фактической конкурентности.
- Tool calling вероятностный. Приложение обязано валидировать имя инструмента и
  JSON-аргументы по схеме, задавать таймауты и не исполнять произвольные команды.
- Модель не должна самостоятельно принимать закупочное решение: цены,
  наличие, реквизиты поставщика и итоговый расчёт проверяются детерминированным
  кодом, а вывод показывается пользователю с источниками.
- До интеграции нужен небольшой golden set на русском: уточнение модели товара,
  нормализация характеристик, сравнение аналогов, объяснение ранжирования,
  корректный вызов каждого инструмента и отказ при нехватке данных.
- Для воспроизводимости после пилота следует закрепить digest Docker-образа,
  revision модели и параметры sampling. Рекомендуемый старт для анализа:
  `temperature=0.1`, `top_p=0.9`.
- Более новая Qwen3.5-35B-A3B INT4 потенциально сильнее, но для MVP не выбрана:
  она требует более нового serving stack, сторонней 4-битной сборки для этого
  объёма VRAM и отдельной проверки parsing tool calls.
