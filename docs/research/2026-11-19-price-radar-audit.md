# Аудит Price Radar на 19 ноября 2026 года

**Работоспособность — 7/10. Архитектура — 7/10. Готовность к расширению эксплуатации — 5/10.** Это инженерные оценки по наблюдаемым сценариям. Поиск, фильтры и экспорт работают. Надёжность покупки зависит от свежести и региона данных поставщика. Первыми стоит закрыть транспорт для входа, диагностику отказов и сохранность данных.

Оценка 7 означает проверенный основной сценарий с существенными ограничениями. Оценка 5 означает отдельные работающие механизмы без полного доказательства надёжности при сбоях. Баллы не усредняются.

## Что проверено

- Прод: checkout `b2295714`. Последний деплой Search и Analysis выполнен из этого ref. Gateway и Web по журналу выпущены из `52713b5f`. Контейнеры работают, vLLM healthy. Диск заполнен на 37%, свободно около 1,1 ТБ. Снимок VRAM двух RTX 4090 — 18 413 и 23 411 МиБ из 24 564 МиБ на каждой. Это единичный замер, запас под дополнительную нагрузку не оценивался.
- Свежий поиск `12400F` через Search внутри продового контура, только NETLAB. Завершился за 1,44 с и вернул две строки с заявленным наличием, без демо. SSE отдал HTTP 200 и завершённый снимок. Экспорт вернул HTTP 200 и XLSX с сигнатурой ZIP. Вкладка Excel отдельно не открывалась.
- Analysis применил фильтр «только в наличии». На вопрос о сравнении модель не привязала одну цену к названной карточке. Проверка отклонила ответ. Детерминированный ответ вернул две ссылки, обе совпали с предложениями из текущего снимка. Один запрос показывает поведение защиты, долю принятых ответов по нему оценить нельзя.
- Продовый HTTP вернул страницу входа, Gateway отклонил запрос без сессии с HTTP 401. Playwright проверил экран входа при 1440×900 и 390×844, горизонтального переполнения нет. Сторонний запрос шрифта не загрузился. Внутренний браузер дважды завершился по таймауту.
- Локальный Playwright при ширине 390 px прошёл вход под тестовым менеджером, поиск, получение трёх явно помеченных демо-предложений и включение фильтра «только в наличии». Горизонтального переполнения и ошибок JavaScript не было. Модель на рабочей машине не запускалась.
- Последние контрольные запросы прошли у восьми активных источников. Время отдельной проверки — от 0,11 до 33,6 с. Это один запрос на источник, поэтому доступность всех товаров и скорость параллельного сбора по этим данным неизвестны. DNS в поиске отключён. Ранее на живом запросе про чернила Ситилинк ошибся, а Авито превысил таймаут.
- Последний недельный отчёт, 18 ноября по Москве: 32 запроса, 90,6% по внутренней метрике верхних трёх строк маркетплейсов, 27 сценариев без ошибок в верхних строках, два пустых поиска. Проверка основана на правилах для названия и артикула. Полнота выдачи, фактические остатки и конкурентная точность этой метрикой не измеряются.

## Архитектура

| Контур | Что работает | Ограничение |
| --- | --- | --- |
| Web → Gateway → Identity | Единый внешний API, сессия, роли, разделение пользовательской истории, корзины и отслеживания. | Изменения пароля и профиля в Identity хранятся в памяти. По коду перезапуск возвращает данные из конфигурации. |
| Gateway → Search → адаптеры | Единый контракт источника, параллельный сбор, частичные результаты, коды отказа, таймауты, Excel, контрольные запросы. | Поиск и последний успешный ответ источника хранятся в памяти Search. При отказе старые строки могут войти в текущую выдачу без отдельного машинного статуса свежести у каждой строки. |
| Gateway → Analysis → vLLM | Условия и отбор считаются кодом. Модель объясняет, ссылки формирует сервер, при отказе работает расчёт. | В продовом замере модель корректно отсеялась, но полезность её объяснений пока не доказана на группе типовых запросов. Счётчики ответов сбрасываются с перезапуском Analysis. |
| Хранение | История запросов, корзина, отслеживание, история цен и отчёты используют файлы на Docker-томах. | Единственный экземпляр наполняет эти файлы. Не нашёл в репозитории сценарий восстановления из резервной копии. Проверка восстановления на сервере не выполнялась. |
| Выпуск | CI проверяет TypeScript, деплой идёт из указанного Git ref, профиль Chrome сохраняется при обычном обновлении. | Скрипт не проверяет работоспособность поискового сценария после сборки и не запускает откат автоматически. Нет единого машинно читаемого состава работающего релиза. |
| Эксплуатация | Есть контрольные запросы к источникам, недельный замер выдачи и журнал отказов модели. | Основной health скрывает отказ зависимостей за `status: ok`. Отдельных доказательств внешних оповещений об отказе и успешного восстановления не получено. |

Границы компонентов соответствуют задаче. Адаптеры можно менять независимо от таблицы и модели. Главная сложность сосредоточена в различиях источников, двух последовательных проверках релевантности и в состоянии, распределённом между процессами и файлами. Для текущего объёма я бы сохранил Compose и адаптеры. Выделение новых сервисов, Redis и Kubernetes стоит рассматривать после подтверждённых ограничений по нагрузке или восстановлению.

## Приоритеты и критерии готовности

| Приоритет | Вывод | Проверка исправления |
| --- | --- | --- |
| P0 перед расширением доступа | На проверенном адресе экран входа отдаётся по HTTP. HTTPS на том же IP отклонён клиентом из-за несовпадения имени сертификата. Другой действующий корпоративный HTTPS-адрес в рамках аудита не подтверждён. | Рабочий адрес с доверенным сертификатом, HTTP перенаправляет на HTTPS, cookie сессии выдаётся с Secure. Проверить вход и выход. |
| P1 | При отказе Search, Identity или Analysis нужен отдельный сигнал. Общий health сейчас показывает только доступность Gateway и косвенный режим работы. | Проверка готовности и диагностика зависимостей в тестовом окружении. Отказ источника виден как частичная деградация, отказ поиска вызывает отдельное оповещение. |
| P1 | Восстановление данных и состояние Identity. | Поднять копию из резервной копии на отдельном окружении. После перезапуска сохраняются изменённый пароль, профиль, история и корзина. Для активного поиска определить срок жизни и понятное поведение при перезапуске. |
| P1 | Покупателю нужна сопоставимая цена на точный вариант и явный статус свежести. | В каждой строке видны источник, время, статус кеша и регион или его отсутствие. Для K380 отдельно клавиатура, версия, комплект и запчасти. Для 12400F отдельно BOX/OEM. Кеш и неопределённые варианты не получают отметку лучшей доступной цены. |
| P1 | Релизный контроль охватывает преимущественно TypeScript. | Подключить Python-проверки, устранить расхождение количества коннекторов в тесте и после деплоя прогонять login → поиск → SSE → фильтр → Excel на выделенной учётной записи. Зафиксировать состав сервисов и проверить откат в тестовом окружении. |
| P2 | Достоверность и полезность ИИ надо измерять вместе. | Выполнять набор фиксированных диалогов, считать принятые объяснения и причины отказа. Проверить сравнения двух карточек одного продавца и упоминания вроде «вторая карточка». Сохранить серверную проверку цен и ссылок. |
| P2 | Точность и полнота поиска требуют разных метрик. | Добавить ручную разметку верхних результатов, долю запросов с найденным точным артикулом, время до первого результата и до завершения. Отдельно считать покрытие и возраст данных по каждому поставщику. |

## Воспроизводимость и ограничения

- Локальный checkout `6f08626f`, два коммита впереди `origin/main`. Исправление колпачков K380 относится к локальному коду. GitHub CI для продового `b2295714` и последнего опубликованного `dbf30eb5` прошёл.
- `npm test` — 780 прошли. `npm run typecheck` и `npm run build` — успешно. `git diff --check` — успешно.
- Python MCP, `.venv/bin/pytest -q -m 'not live and not cdp'` — 1746 прошли, 74 пропущены, 5 исключены, один упал. `test_the_mounts_table_was_read` ожидает минимум 14 зарегистрированных коннекторов, извлечено 13. Падение само по себе не доказывает отказ конкретного подключённого магазина.
- Начальный SSE-пробник ждал закрытия подключения и получил таймаут. Повтор с чтением до завершённого снимка прошёл. Контракт сервера оставляет поток открытым, пока клиент его не закроет. Живую последовательность промежуточных SSE-событий через внешний прокси не измерял.
- Проверки API на проде выполнялись внутри контура. Полного браузерного прогона за входом на проде, нагрузочного теста, отключения сервисов, восстановления из копии и оценки фактических остатков не было. Продовый поиск создал обычный снимок и мог добавить точку истории цен. Конфигурация и версия на проде не менялись.
- Использованы Graphify, Serena, ECC production-audit, Ponytail audit, architecture-analysis и browser-verification. Context7 не понадобился для проверки локальных контрактов. Security review и Semgrep исключены по прежнему указанию.
