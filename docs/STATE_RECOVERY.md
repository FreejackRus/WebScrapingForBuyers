# Проверка готовности и восстановление Price Radar

`GET /api/v1/health` сохраняет прежний формат для интерфейса.
`GET /api/v1/ready` проверяет Identity, Search и Analysis параллельно с
ограничением 3 секунды на запрос. HTTP 200 означает доступность всех трёх.
HTTP 503 со статусом `unavailable` означает отказ Identity или Search.
HTTP 503 со статусом `degraded` означает отказ Analysis при доступном
поиске. Ответ содержит только имена компонентов и статусы.
Для внешнего мониторинга проверяйте `/api/v1/ready` под префиксом приложения.
Канарейки поставщиков и состояние модели проверяются отдельно. Этот маршрут
не отправляет запросы в магазины и не запускает модель.

## Снять и проверить копию

На сервере из каталога выкладки, в приватный каталог с достаточным местом:

```bash
python3 scripts/backup-state.py capture /path/to/private/radar-YYYYMMDD.zip
python3 scripts/backup-state.py verify /path/to/private/radar-YYYYMMDD.zip
python3 scripts/backup-state.py restore /path/to/private/radar-YYYYMMDD.zip /path/to/new-restore-dir
```

Копия включает JSON-данные Gateway и Search: корзину, отслеживание, историю
запросов и цен, результаты контрольных поисков и оценки. Архив содержит
пользовательские данные. Файл создаётся с правами владельца, выводится
только список отсутствовавших файлов. Храните проверенную копию за пределами
того же сервера с доступом владельца и сроком хранения по правилам команды.

Файлы читаются независимо, поэтому это не общий транзакционный снимок.
Отсутствующий файл перечисляется отдельно. Повреждённый файл прерывает
копирование. Проверка сверяет разрешённые пути, содержимое архива и SHA-256.
Восстановление создаёт новый каталог и отказывается перезаписывать существующий.

## Пробное восстановление

1. Распакуйте архив в новый каталог. Сверьте число файлов с командой verify.
2. В отдельном Compose-проекте создайте чистые тома для Gateway и Search.
   До запуска обоих сервисов перенесите файлы из одноимённых каталогов
   распаковки в соответствующие `/data`. Проверьте владельца и права.
3. Запустите изолированный контур. Убедитесь, что через API загружаются
   история, корзина, отслеживание и история цен. Для проверки пользовательских
   данных идентификатор тестового пользователя должен совпадать с владельцем
   тестовых записей. При таком прогоне используйте синтетические записи.
4. Документируйте дату копии, время восстановления и исход проверки. Подмена
   рабочих томов требует отдельной процедуры остановки и проверки.

Активные поиски, резервные строки в памяти и сессии Chrome не входят в архив.
При обрыве потока поиск можно повторить из поля запроса или истории.
Настройки Identity, секреты и GPU-модель в этот архив не копируются.
